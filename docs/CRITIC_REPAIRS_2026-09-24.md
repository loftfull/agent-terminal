# Исправления по заключению критика

Принят приоритет законченной передачи истории. Новые подсистемы не добавлялись.

P0: build_view теперь начинает с всех канонических полей, а затем добавляет
производные поля панели. Исходная schema сохранена как canonical_schema;
schema оболочки остаётся terminal-view/v1. chats/conflicts/search_queue и
development_lines доступны без переименования. Существующие copy/download
сериализуют эту же оболочку. Это экспорт данных, не резервная копия файлов
журнала, вложений, окружения или исполняемый импорт в другую модель.

Новый регрессионный тест берёт непустые реальные lineage/conflicts/search_queue,
сравнивает ВСЕ канонические поля после JSON roundtrip в отдельном процессе,
проверяет равенство встроенному HTML snapshot. Пять dashboard тестов PASS.
Полный локальный прогон: 214 Python тестов PASS (10,446 с), Node проверки
сообщений/избранного PASS. Doctor: журнал/replay/snapshot/структура PASS;
WARN сохраняется для ненастроенных host-источников/hooks и локального Playwright.
Браузерные действия copy/download на новой версии пока не испытаны; семантическая
приёмка другой моделью и автоматический переход после лимита остаются открыты.

P1: README отделяет текущую candidate-ветку от исторического v0.6 CI checkpoint.
Локальный SHA в журнале помечается историческим наблюдением; live HEAD не
выдаётся за зафиксированное состояние. Исторические записи не переписываются.

Открыты: причинная диагностика прежней потери хвоста, bootstrap durability,
полная передача с квитанцией нового читателя, реальная host/Windows приёмка,
контекстный бюджет и внешний A6. Увеличение payload из-за сохранения пропущенных
полей допустимо для исправления потери; обещания оптимизации не делаются.
