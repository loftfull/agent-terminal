# Основа службы памяти: исследование и первый адаптер

Дата: 2026-09-23. Статус: экспериментальная реализация, не полная приёмка агента.

## Решение

Сохраняем журнал FIX источником истории. Добавляем официальный MCP Python SDK как
транспорт для чтения памяти другим AI-host. Это позволяет повторно использовать
готовый протокол, не переносить доказательную историю в новую систему и отдельно
проверить сохранение ограничений, статусов фактов и источников.

Терминал запускает процесс, но сам не является хранилищем. История остаётся на
диске после завершения процесса. Текущий адаптер работает по stdio; постоянная
служба, HTTP, авторизация удалённых клиентов и автоматический запуск ещё не реализованы.

## Проверенные исходные проекты

| Решение | Лицензия репозитория | Применение и ограничение |
|---|---|---|

| [Basic Memory](https://github.com/basicmachines-co/basic-memory) | AGPL-3.0 | Кандидат на поисковую проекцию Markdown/SQLite. Локальный режим бесплатный; облако отдельно. Не заменяет журнал. |
| [projectmem](https://github.com/riponcm/projectmem) | MIT | Полезный образец учёта попыток, исправлений и предварительной проверки прошлых ошибок. Второй журнал сейчас не вводим. |
| [Graphiti](https://github.com/getzep/graphiti) | Apache-2.0 | Возможный следующий слой временных связей. Требует графовой БД и моделей; для первого этапа избыточен. |
| [Mem0](https://github.com/mem0ai/mem0) | Apache-2.0 | Память и извлечение с моделями/эмбеддингами; дополнительная инфраструктура и проверка точности извлечения. |
| [Letta](https://github.com/letta-ai/letta-code) | Apache-2.0 | Отдельная агентная среда; смена среды не нужна для текущей задачи. |

Это качественное сравнение кода/документации и архитектуры, не сравнительный
бенчмарк шести продуктов. Число звёзд не использовалось как критерий качества.
Ни одно решение не гарантирует безошибочность анализа. Платные API не требуются
для реализованного адаптера; использование модели оплачивается по условиям её host.

## Запуск из выбранной рабочей копии

Требуется Python 3.12 (испытанная версия):

```sh
python -m venv .venv
python -m pip --version
# Далее использовать Python из созданного окружения:
# Windows: .venv\Scripts\python.exe
# Linux/macOS: .venv/bin/python
.venv/bin/python -m pip install -r requirements-mcp.txt
.venv/bin/python project_history_mcp.py --root /absolute/path/to/FIX --project-id project-history-agent
```

На Windows замените `.venv/bin/python` на `.venv\Scripts\python.exe`.
Ручной запуск ожидает MCP-ввод, поэтому обычное приветствие в терминале не выводится.
Версия SDK закреплена; транзитивные зависимости пока не зафиксированы lock-файлом.

В настройках host, который поддерживает локальные stdio MCP-серверы, задайте:

```json
{
  "mcpServers": {
    "project-history": {
      "command": "/absolute/path/to/FIX/.venv/bin/python",
      "args": [
        "/absolute/path/to/FIX/project_history_mcp.py",
        "--root", "/absolute/path/to/FIX",
        "--project-id", "project-history-agent"
      ]
    }
  }
}
```

Это пример параметров процесса, не универсальный формат настроек всех host.
Браузерный ChatGPT этим локальным запуском автоматически не подключается.
Не публикуйте stdio-процесс через незащищённый HTTP-туннель.

## Реализовано

- `get_project_context`: память, ограничения, пути, ветви и незакрытые вопросы.
- `search_evidence`: буквальный поиск по зарегистрированным событиям с пагинацией.
- `get_event`: событие с зарегистрированными ссылками на источники.
- Проверка целостности журнала, структуры и project_id перед выдачей.
- Сохранение исходного evidence_status; наличие записи не доказывает истинность.
- Секция `CRITICAL_CONSTRAINTS` в Markdown, чтобы требования не терялись при передаче.

Одинаковый GitHub URL недостаточен для определения проекта: в FIX найдены и ветви
агента, и InstaVault. Адаптер требует явные checkout и project_id. Сходное название
чата остаётся только поисковой подсказкой.

## Проверка и оставшиеся этапы

```sh
.venv/bin/python -m unittest tests.test_mcp_bridge -v
```

Тест включает настоящий дочерний stdio-сервер и MCP-клиент, читающие журнал FIX.
Другие проверки используют явно синтетические данные: сохранение ограничений и
источников, запрет чужого project_id, обнаружение изменения журнала, отсутствие
записи при чтении, валидация поискового запроса.

Это не испытание полноты анализа INSTA. Предстоит импортировать доступные реальные
чаты INSTA, сопоставить их с конкретными версиями, измерить пропуски требований и
ложные связи, затем провести передачу независимой модели. Остановленная ветвь
не объявляется тупиковой без доказательств причин и последствий. Отсутствие ответа
старой модели не означает согласие. Постоянный процесс и автоматическое подведение
итогов дня требуют отдельной проверки перезапуска и пропущенных запусков.
