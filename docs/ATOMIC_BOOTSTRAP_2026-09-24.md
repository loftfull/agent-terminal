# Атомарное первоначальное создание журнала

Воспроизведён сбой bootstrap_journal_from_state: прерывание генерации мутаций
после двух записей оставляло опубликованный частичный файл; повторный bootstrap
отказывал FileExistsError. Это конкретный воспроизводимый дефект, не доказанная
причина прежнего естественного отката хвоста.

Исправление использует существующие ProjectLock и atomic_write_text:
проверка отсутствия файла внутри общей writer-блокировки, redaction и replay
всех начальных мутаций в памяти, построение полной hash-chain, одна публикация
через fsync временного файла и os.replace. Формат записей прежний, существующие
журналы не переписываются. Новых зависимостей и подсистем нет.

Проверки:
- Ошибка во время подготовки: файл отсутствует, повторный bootstrap успешен.
- Ошибка перед rename: файл отсутствует; существующий журнал не перезаписывается.
- Потеря подтверждения после rename: файл уже полный, verify/replay проходят;
  вызывающая сторона обязана сверить существующий журнал, а не удалять его.
- Два одновременных создателя: один победитель, второй FileExistsError; файл
  содержит полный state победителя, без смешения данных.

Полный прогон после исправления и первых трёх тестов: 218 tests PASS, 10,204 с.
После добавления конкурентной проверки: все 4 bootstrap tests PASS. Проверки
используют внедрение исключений и конкурентные потоки; физическое отключение
питания, Windows и сетевые FS в этом цикле не испытаны. OS-lock межпроцессные
проверки существуют отдельно. Directory fsync остаётся best effort текущего
atomic_write_text. Память расходуется на полный начальный журнал.

Bootstrap сохраняет существующую семантику replay/preflight; полной структурной
валидации, эквивалентной runtime batch audit, здесь не добавлено. Низкоуровневый
append_mutation и прочие многошаговые workflows этим исправлением не становятся
атомарными. Старые повреждённые/частичные файлы не удаляются автоматически.
Следующий приоритет: проверить оставшиеся прямые writers и восстановление после
оборванной записи с сохранением доказательств; full A6 и автоингест остаются открыты.
