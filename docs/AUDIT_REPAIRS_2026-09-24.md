# Исправление независимого аудита

Исходные B1–B5 подтверждены отдельным аудитором на временных fixtures.
Решение: исправить границы существующего ядра; не заменять хранилище одновременно
с исправлениями. Поиск и сравнение GitHub-кандидатов выполнены в BLIND_AUDIT.

- B1: готовая зависимость wolph/portalocker3.2.0 (BSD-3-Clause), OS-backed lock
  вместо удаления по возрасту. Файл остаётся после release; crash освобождает OS lock.
  Старые процессы FIX остановить перед обновлением: смешанный протокол не поддержан.
- B2: применение redacted мутации к отдельному replay-состоянию под writer lock
  ДО записи. Оба writer API отказывают missing patch без изменения bytes. Это
  replay preflight, НЕ полная structural validation и НЕ атомарность source+event batch.
  Неверные ссылки, например отсутствующий source ID события, остаются отдельным
  риском; строгий batch-aware validator — следующий этап. JSONL не мигрирован.
- B3: lifecycle проверяет project ID существующего журнала/мигрируемого snapshot
  и current chat до изменения истории; ошибочное project B в root A отклоняется.
- B4: текстовые Cookie/Set-Cookie headers маскируются целиком до persistence.
  Обычный следующий текст сохраняется. Старые секреты аудитом не обнаруживались;
  универсальное распознавание секретов не заявляется. Gitleaks не установлен.
- B5: native handoff передаёт полную Markdown-проекцию; нет обрезания по3500 chars
  или текстовому heading, который может находиться внутри пользовательского goal.
  Бюджет размера не ограничен; это цена сохранения обязательного контекста.

Независимый review подтвердил закрытие исходных пяти inputs. Найденные им две
дополнительные проблемы исправлены: установка core в CI verify и heading collision.
Новые5регрессионных проверок: live aged lock с отдельным процессом + kill/reacquire,
неизменные bytes при rejected patch, unchanged journal при чужом project ID,
отсутствие synthetic cookie values в сохранённом файле, длинные constraints и
heading collision. Два прежних теста обновлены для корректного persistent-lock
контракта; проверяется освобождение блокировки, а не удаление pathname.

Полная локальная проверка:209tests PASS,10.244s. Windows CI ещё не подтверждён
этим протоколом. Реальные чаты в этом цикле повторно не импортировались: проверялись
точные дефекты записи и handoff на синтетических изолированных входах.
Новый код не является полной внешней A6-приёмкой.
