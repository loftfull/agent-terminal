## Результат повторного аудита

Baseline: 223 Python tests PASS. Профильные межпроцессные тесты теперь запускаются
из отдельного venv с закреплёнными requirements; прежняя ошибка отсутствия mcp
в дочернем Python была ограничением окружения, а не доказанным дефектом проекта.

Подтверждён незакрытый сценарий: каждый read_layer согласован внутри одного
вызова, но разные страницы не были связаны ожидаемым journal_tip. Legacy чтение
по-прежнему разрешено; безопасная последовательность требует явно передавать tip.
Arena предложила полезную идею, но её код содержит отсутствующие функции,
фиксированные ограничения, другую схему событий, несовместимый Server.tool,
пустой mock writer и неисполненный PASS. Этот код не применялся.

## Реализовано

- Необязательный keyword-only expected_journal_tip после сохранённого vault.
- Проверка SHA-256 по той же паре state/tip, которую вернул HistoryReader.read().
- STATE_CHANGED без страницы/источников при несовпадении. Клиент обязан удалить
  накопленные страницы и начать чтение заново. Старый снимок сервер не хранит.
- Существующий MCP read_context_layer расширен; project/root остаются привязаны
  при create_server. SDK игнорирует лишний project_id: он не переключает проект.
- CLI context принимает --expected-journal-tip. Старые поля ответа и receipt
  сохраняются. Неверный формат tip отклоняется до обращения к истории.
- CI включает новый тест, а также ранее отсутствовавшие bootstrap/doctor tests.

GitHub-first: etcd-io/etcd, закреплённая ревизия и границы адаптации описаны в
GITHUB_SOLUTIONS.md. Код upstream не копировался, зависимостей не добавлено.

## Открытые границы

- Windows CI нового кода требует отдельного удалённого прогона.
