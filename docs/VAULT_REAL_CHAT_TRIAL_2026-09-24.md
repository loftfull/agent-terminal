# Испытание готовых компонентов на реальном чате

Источник: ранее сохранённый Vibe Stack Discovery, 18 сообщений, 94 726 символов.
Это не полный корпус INSTA. Сырые timestamps и model metadata сохраняются;
девять временных инверсий не исправлены задним числом.

## Наблюдаемый результат

- Реальная команда проверки в дочернем процессе: PASS,18 сообщений без потери полей.
- Runner записал внешний checkpoint в SQLite eventsourcing. Новый MCP-процесс
  с `--vault` получил все18 сообщений страницами по7; witness совпал:82 записи.
- На отдельной копии искусственно возвращено состояние ДО запуска. Внутренняя
  hash-chain оставалась валидной, но witness и MCP отклонили такой журнал.
- Восстановление в НОВУЮ папку прошло; новый MCP снова получил18 сообщений.
  Полное сравнение текста, ролей, дат и metadata: PASS. Повторный импорт:0добавлений.
- После добавления source-backed отчёта в отдельно восстановленную финальную
  память89 записей совпадают с vault version3; task остаётся review, accepted=false.

## Ошибки, найденные в этом цикле

Независимый аудит воспроизвёл и исправил: отсутствие проверки секретов в JSON-ключах
перед backup; неконтролируемое исключение повреждённой SQLite; symlink/unsafe manifest;
запись lock-файла при readonly verify; несогласованные лимиты сериализации.
Runner больше не создаёт исчезнувший witness молча: запуск с vault требует ранее
инициализированную проверяемую копию. Конкурентные capture не перезаписывают друг друга.

190 локальных тестов PASS. Независимый связанный набор:47 PASS, в том числе19vault.
JavaScript syntax check PASS; полноценная браузерная визуальная приёмка остаётся
ENV_BLOCKED. Первая Windows CI выявила утечку SQLite handle при ошибке настройки соединения
в eventsourcing9.5.5 и незакрытые fault-injection соединения тестов.
Добавлен локальный connection pool с закрытием ресурса при setup failure;
BSD3 attribution сохранена. Новый regression удерживает raw connection и
проверяет, что оно уже закрыто и DB можно сразу переименовать/удалить.
Повторный связанный набор48PASS. Windows/Linux CI фиксируются в PR для конкретного SHA.

## Что не закрыто

Причина исторического исчезновения хвоста неизвестна. Контролируемый rollback —
отдельная инъекция сбоя, не объяснение старого инцидента.

Первый новый эксперимент остановился на stale lock при окончательном handoff;
readonly verify после этого исправлен и проверен. Второй полный recovery trial
прошёл, но поздняя запись дополнительного отчёта в его исходную memory снова
была заблокирована существующим lock. Причина появления/возврата lock не доказана.
Файл не удалялся. Отчёт добавлен в новую восстановленную final-memory; это не
скрытое исправление старых следов. Старые и новые неуспешные каталоги сохранены.

Внешний witness обеспечивает обнаружение расхождения и проверенное восстановление
последней сохранённой точки в испытанном сценарии. Он не гарантирует сохранность
при откате всего компьютера или DB вместе с журналом. Для следующего уровня нужен
отдельный backup backend и restore drill за пределами этой среды.

ACP hosts, внешнее резервное хранилище, оригинальные INSTA-чаты и настоящие
скриншоты сборки не испытаны. Общая приёмка проекта остаётся открытой.
