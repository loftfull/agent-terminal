# Согласованное чтение doctor — 2026-09-24

Исправление дефекта из STATE_AUDIT_2026-09-24.md, baseline local 4362791.
Новой зависимости нет: используется существующий ProjectLock/Portalocker 3.2.0.
Это исправление чтения, не новый collector и не доказательство причины прежнего
rollback. Исторический FAIL сохранён в журнале.

## Причина и изменение

Doctor проверял hash chain, делал replay и читал snapshot в разные моменты.
Runner публикует running после запуска дочернего doctor. Старый reader мог
сравнить разные поколения. Regression с отдельным writer воспроизвёл FAIL
на старом коде при корректно сохранённых данных.

Теперь проверка берёт snapshot lock, затем journal lock: в таком порядке она
не пересекает публикацию snapshot или запись cooperative journal writer.
Обе блокировки освобождаются до внешних probes. Если журнал опережает checkpoint,
проверка отпускает locks и повторяется: максимум 3 чтения, пауза 50 ms.
Она не переписывает snapshot и не исправляет источник. Устойчивое расхождение
остаётся FAIL; повреждённый hash chain не получает повтор ради PASS.
Занятая блокировка ограничена timeout и даёт FAIL.

## Испытания

Четыре новых regression: конкурентная публикация между replay/read, постоянный
stale snapshot без автопочинки, завершение отложенного checkpoint, corruption.
Первый тест дал FAIL до исправления. После исправления полный unittest:
**223 tests PASS, 10.631 s**, через terminal_runner:
`EV-RUN-f29698a5251840b9954ec29777bf567d-succeeded`.

Doctor запущен тем же runner на настоящем журнале FIX:
`EV-RUN-b8e516a75e9b4486abce0ec1a67f1930-succeeded`.
Получено **WARN**, integrity/replay/snapshot/structure PASS; использованы
2 попытки, то есть промежуток до checkpoint действительно встретился.
WARN: нет настроенного локального history adapter, hooks и Playwright.
Это не испытание новых реальных INSTA сообщений и не A6.

## Границы

Согласованность действует для writers, соблюдающих имеющиеся locks.
Медленный checkpoint после предела повторов всё ещё приводит к FAIL — сознательно
не превращаем отсутствие подтверждения в успех. Блокировки могут задержать writer
на время replay/audit; большой архив и пользовательский Windows в этом цикле
не измерялись. Другие readers и оставшиеся многошаговые writers не исправлялись.

Следующий шаг: сквозная проверка передачи связанной истории на доступных исходных
чатах с сохранением требований, заменённых решений и явных пробелов покрытия.
